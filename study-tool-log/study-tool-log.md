# 학습 도구 로그

- 학습에 도움이 되는 도구를 만들고, 기록합니다. 필요하면 코드를 남깁니다.

## **도구 이름**

TS-JS 변환 및 결과 분석 터미널

## **도구 유형** (예: GPTs, gems, Claude Code(skill, command, agent, ...) Chrome Extension, CLI, 웹사이트 등)

Gemini Canvas

## **해결하려는 문제**: 어떤 학습 상의 불편/문제를 해결하려 했는가?

TypeScript를 처음 공부할 때, TS 문법이 실제 JavaScript로 어떻게 변하는지 체감하기 어렵고, 특히 TS에서 에러로 잡아주는 코드가 JS 환경에서는 왜 위험한지를 실시간으로 비교하며 학습할 수 있는 환경이 부족하다는 문제를 해결하려 했습니다.

## **어떻게 만들었는가**: 간단한 제작 과정

UI 설계:좌측에는 TS 입력창, 우측에는 변환된 JS 결과창을 배치하고 하단에 각각의 실행 결과를 보여주는 '터미널' UI를 구성했습니다.

변환 로직: 정규표현식(Regex)을 활용해 TS 특유의 문법(Interface, Type Annotation, Generic 등)을 제거하고 순수 JS로 변환하는 간이 트랜스파일러 기능을 구현했습니다.

결과 시뮬레이션: 사용자가 입력한 코드 패턴을 분석하여, TS 환경에서의 '컴파일 에러 메시지'와 JS 환경에서의 '런타임 실행 결과(Console)'를 가상으로 생성하여 보여주도록 로직을 짰습니다.

분석 피드백: 코드 변환 과정에서 어떤 보호막(타입 시스템)이 사라졌는지 요약해 주는 분석 섹션을 추가했습니다.

## **어떻게 도움이 되었는가**: 실제 사용 경험과 효과

단순 문법 암기가 아니라 "JS의 런타임 에러를 어떻게 TS가 미리 방지하는가"라는 관점으로 공부 방향을 잡는 데 큰 도움이 되었습니다. TS가 빨간 줄로 경고하는 코드가 JS에서는 조용히 undefined를 뱉으며 실행되는 것을 나란히 비교해 봄으로써, TS 도입의 필요성을 논리적으로 파악하게 되었습니다. interface나 타입 선언이 JS로 변환될 때 완전히 증발하는 것을 보며 "TS는 개발 단계의 도구"라는 개념을 확실히 이해할 수 있었습니다.
